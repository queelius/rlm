# Composable interfaces and partition invariance: bounded fallback

Status: hypothesis queue, not a pivot from the sealed helper study. This is a
mechanism test only if the current question-planner/helper study has no useful
held-out signal.

## Local lesson and precise unknown

Local data supports an interface problem, not learned recursive composition.
The prior fixed five-item child plus Python aggregation comparison improved new
aggregate tasks from 1/24 to 15/24 when only child weights changed; the freely
acting RLM reached 6/24. The [cross-experiment finding](/project/alex_phd/runs/rlm-research-r4/analyses/cross-experiment-synthesis-2026-09-09/FINDINGS.md)
also records coverage/parsing and root-Python failures, though 22/23 fully
covered episodes aggregated faithfully. Replacing model helper replies by known
local labels moved 26/48 to 44/48, but residual failures were root
calculation/recovery ([helper intervention report](../../docs/research-checkpoints/2026-09-12-helper-intervention.md)).
These are diagnostics, not evidence that a return schema, recursion depth, or
partition-invariant policy transfers.

The current frozen-trace aggregation probe adds a warning: full source beat
trace-only final aggregation 78/128 to 74/128 with invalid helpers retained as
zeros ([aggregation finding](AGGREGATION-FINDINGS.md)). A syntactically valid
compressed message can omit the fact needed later. Also, helper SFT teacher-binds
earlier gold train answers, so it cannot establish a deployable multi-level
contract without predicted-history evaluation.

Do **not** recreate the existing bicycle/helmet or purchase/local-winner
cross-partition joins. The Sep 9--10 study already addressed them. Nor rerun
the B05 fixed three-stage ETL/singleton comparison: singleton extraction won
10/12 versus list/vector 4/12. Those results motivate a stronger held-out
composition test, not another way to show small requests help.

**Unknown:** After holding leaf capacity and budget fixed, does an
evidence-carrying message contract improve verified correctness under a new
valid partition, and is any gain due to exact aggregation, bounded delegation,
or the contract? Agreement alone is not evidence: an always-wrong answer is
partition invariant.

## Prior-art boundary

[RLM](https://arxiv.org/abs/2512.24601) already allows external-context
inspection, recursive calls, and model-authored Python aggregation. It reports
both useful scaling and long-tail cost; it does not establish a sufficient
intermediate textual interface under re-partitioning.

[lambda-RLM](https://arxiv.org/abs/2603.20105) is closer: it provides a typed,
deterministic Split/Map/Filter/Reduce runtime with bounded neural leaves.
Consequently, neither typed composition nor exact program aggregation alone is
a novelty claim. The narrower possible contribution is learned production/use
of an evidence-carrying sufficient message contract, tested on unseen surface,
structure, and depth while retaining unrestricted-Python RLM control.

The supplied `Python is the Counterfactual` OpenReview page (`k2NrIxm4Do`) was
challenge-gated, so its method remains unverified here. Do not make a
counterfactual-credit novelty claim; the proposed test has no credit-assignment
component.

## One-A100-hour pilot -- not yet ready

Do not launch this on the present assets. B05's `etl_catalog` has a useful
strict evaluator and solvers, but fixes three stages and one surface renderer;
its `history_depth` changes log/history depth rather than composition depth and
its width/history axes also change input length. The purchase protocol similarly
fixes a two-product query. Thus neither can support the required independent
surface/depth/length holdouts without a nontrivial generator extension. Existing
B05 results (singleton 22/24 versus vector 10/24; fresh normalization 1/24 to
9/24; wider width 12/20 at zero exact; RL exact 0/18) must not be relabeled as
a new composition contribution.

Only after CPU preparation supplies a *new*, pre-frozen separable family should
the following one-hour run be admitted. Make each case an exactly scored
set/count/sum requiring cross-chunk joins, with public record IDs, evidence
IDs, distractors, and two semantics-preserving partitions. Freeze 24 underlying
test cases, their two partitions, seeds, and evaluator before any call. Exclude
chronology-sensitive operations.

Run four matched arms with the released 4B and fixed per-role decoding caps.
They have matched *opportunities* and declared upper caps, not equal actual
compute: Direct necessarily uses fewer calls, and actual tokens/calls must be
reported rather than inferred from caps.

| Arm | Leaf return | Combination | Distinguishes |
|---|---|---|---|
| Direct | none | one model answer | no delegation |
| Free leaf | natural-language local answer | model final | ordinary delegation |
| Contract + model | per-entity predicate set, record IDs, unresolved set | model final | contract without exact combiner |
| Contract + Python | exactly the same contract | fixed union/intersection/sum | exact aggregation |

Malformed or unresolved contract output scores zero; no host gold or oracle
rows enter a model prompt. The final may see source documents only when that
arm declares it--otherwise a full-source fallback invalidates the comparison.
Save leaf coverage, parser status, exact score, partition pair, and all costs.
At 24 cases x 2 partitions, Free leaf and Contract each require 96 leaf calls;
the Contract leaves may be reused between its model and Python combiners. The
maximum is therefore 192 leaf calls, plus 48 Direct calls and 96 model-combiner
calls: 336 model calls. Python combination adds no model call. Use conservative
384-token leaf and 128-token final caps, report actual cost separately by arm,
and stop at one A100-hour. No training in this first test.

### Generalization separation and controls

Use development only to fix the contract/parser on shallow two-predicate,
two-chunk template family A. Test template family B with renamed entities and
different relation wording, then a structural panel with three predicates and
a depth-three *execution tree*. Three predicates alone are not a three-hop
dependency: freeze an explicit dependency graph and independently vary its
longest dependency path and its execution-tree depth. Match records and call
budget between execution depths two and three. Never tune after observing
either member of a partition pair.

Report exact accuracy, malformed/incomplete rate, coverage, paired partition
agreement, and **both-correct partition accuracy**. The latter is primary for
the invariance hypothesis. Cheap essential controls are exact aggregation of
oracle-complete contract rows (generator/parser validation only), shuffled
valid partitions, model versus Python combination of the same messages, and
free leaves under equal caps. Oracle rows are never a deployment baseline.

Promote only if Contract + Python improves held-out both-correct partition
accuracy over both Free leaf and Contract + model, without hidden final source
access, and survives new surface/topology/depth. A Contract + Python-only win
is a harness/exact-aggregation finding, not learned recursion. A null or
partition-fragile result retires this direction rather than training a schema
on the small family. Record generator commit, seeds, frozen hashes, public
pretraining caveat, and keep an untouched confirmation family before any
publishable claim.
