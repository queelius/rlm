# If action training helps, what did it actually teach?

Two inexpensive follow-ups could prevent an attractive training result from
being misinterpreted. Neither is a queued run or a claim about pending results.

## Household actions: meaning or list position?

The actor chooses a number from the current admissible-action list. If trained
performance improves, repeat a fixed panel with a predeclared permutation of that
list and remap the chosen index to the corresponding native action. Compare both
base and trained actors under the same permutations and budgets. Do not permute
only the trained model or change what actions are available.

This would test sensitivity to the presentation of action choices, not prove
that every failure is positional memorization. A large training-by-permutation
interaction would motivate order-varied demonstrations before a hierarchy claim.
The first exposed-panel screen would add48 episodes for the two flat policies
on12 games/two seeds; estimate30–60 minutes on one A100, cap60 minutes, revising
that estimate from the completed trained-actor timing before acceptance. Preserve
all raw presented lists, indices and native commands. No implementation is needed
until the pending fixed-endpoint comparison establishes a useful competence gain.

## Crafting: using recipe information or remembering the recipe world?

All current crafting tasks share the same generated recipe world. Even different
root goals reuse familiar component names and recipes. If supervised action
training helps, a stronger next test would change the recipe world while keeping
the public query/craft interface and basic task sizes comparable.

First qualify whether the pinned generator supports a separately seeded world
and CPU-verifiable tasks without silently changing tool semantics. Freeze that
world and task selection before model evaluation. Every model must discover
recipes through the same charged public queries; never place host gold plans in
its prompt. Compare the unchanged base and fixed trained endpoint, and distinguish
new recipe relationships from mere item renaming or longer plans.

A bounded16-task/two-policy/two-seed readout would be64 episodes; GPU duration
must be estimated from the pending pilot before acceptance, with an initial
one-hour exploratory cap and incomplete outcomes retained separately. A gain
only in the original world would narrow the claim to shared-world competence.
A retained gain in a changed world would justify investigating reusable query
and quantity-handling skills. It would not by itself establish learned recursive
decomposition or a new method.

These controls are contingent, not obstacles to the already-accepted exploratory
jobs. The next decision remains learning from their completed outcomes.
