# Observational helper-gating diagnostic

On the existing fresh003 64-parent × two-repeat replay, the non-deployable
per-attempt oracle reaches 65/128 for both roots: it takes the better factual
execution or plan-only result after outcomes are known. SFT has 12 plan-only
wins and nine execution wins; RL has nine plan-only wins and 12 execution wins.
This is headroom only, not a gate.

The sole predeclared public rule is: execute helpers iff the generated root plan
has more than two subquestions. It sees only root output length, before helpers
or finals; it uses no hop, support, answer, or outcome feature. This is an
exploratory post-hoc hypothesis motivated by prior three-hop RL observations,
not a replication or a CV classifier.

| Policy | Plan only | Execute | Length rule | Oracle | Rule cost tokens |
|---|---:|---:|---:|---:|---:|
| SFT48 | 56 | 53 | 53 | 65 | 817,301 |
| RL16 | 53 | 56 | 52 | 65 | 914,313 |

The rule fails to recover the oracle headroom: among executed SFT slots it
turns five plan-only wins into execution losses while recovering two; for RL it
turns seven plan-only wins into losses while recovering six. It should be
retired as a deployable skip rule unless a new, predeclared public signal is
tested on a new panel.
