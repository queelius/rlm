\begin{frame}[t]
\frametitle{Can a model learn to find what it needs?}
A recursive language model (RLM) can use tools and ask helper models to solve parts of a task.
\begin{block}{For this study, we returned to a basic skill.}
Can better examples and better tools help a small model finish a multi-step task?
\end{block}
\textbf{Example: Make a wooden pickaxe in a crafting game.}
\begin{enumerate}
\item The model asks which ingredients it needs.
\item It makes the parts and then the pickaxe.
\item The game checks whether the pickaxe actually exists.
\end{enumerate}
\aside{Simplified illustration of TextCraft, our test environment. These experiments use one model with tools, not recursive helper calls.}
\end{frame}

\begin{frame}[t]
\frametitle{We taught the model by showing what to do next.}
We trained copies of the same model to imitate worked examples. This is \textbf{supervised fine-tuning (SFT)}.
\vspace{2mm}

\textbf{Example:} Given ``Make a pickaxe'' and the actions so far, learn to ask for the pickaxe recipe next.
\vspace{2mm}
\begin{columns}[T,onlytextwidth]
\begin{column}{.48\textwidth}
\begin{block}{The teacher knows recipes.}
A program plans the steps using recipes it already knows, then shows lookups and actions.
\end{block}
\end{column}
\begin{column}{.48\textwidth}
\begin{block}{The teacher discovers recipes.}
A program looks up the goal's recipe, discovers the needed parts, then looks up their recipes.
\end{block}
\end{column}
\end{columns}
\vspace{2mm}
Both show lookups. Only the second uses them to decide the route.
\aside{Simplified example. Both sets cover the same 32 training tasks and number of steps, but differ in text and action order.}
\end{frame}

\begin{frame}[t]
\frametitle{The advantage remained when recipes changed.}
Could the models cope when making the same items required different ingredients? We changed the recipes and starting supplies, without retraining.
\vspace{1mm}
\begin{center}
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{lcc}
\toprule
Successful attempts (out of 16) & First repeat & Second repeat\\
\midrule
Teacher knows the recipes & 4 & 1\\
Teacher discovers the recipes & \textbf{6} & \textbf{8}\\
\bottomrule
\end{tabular}
\end{center}
\vspace{2mm}
The lead was small in one repeat and large in the other.\par
\medskip
This is encouraging, but it is still \textbf{one kind of game}.
\aside{Eight goals, two attempts each; all outcomes are known. The quantity error is corrected here too. The smaller difference is too uncertain to establish a clear advantage on its own.}
\end{frame}

\begin{frame}[t]
\frametitle{Let the model choose the step; let code fill the details.}
The model chooses what to make and how much. Code fills in the ingredients using a recipe the model already looked up.\par
\vspace{2mm}
We changed the tool, with \textbf{no extra model training}.\par
\vspace{1mm}
\begin{center}
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{lcc}
\toprule
Successful attempts & Model fills & Code fills\\
(out of 16) & ingredients & ingredients\\
\midrule
Slide 4 recipes, first model & 6 & \textbf{12}\\
Slide 4 recipes, second model & 8 & \textbf{10}\\
Different recipes, first model & 9 & \textbf{14}\\
\bottomrule
\end{tabular}
\end{center}
\textbf{Next question:} Can this division of work help on other tasks?
\aside{Both models learned from discovery examples. These are small, related tests in one game; the smallest gain remains uncertain. We have not shown better recursive planning.}
\end{frame}
