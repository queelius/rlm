\begin{frame}[t]
\frametitle{Can better handoffs make an RLM more reliable?}
In a recursive language model (RLM), a main model can ask helper models to do smaller tasks. We call this exchange of work and answers a \textbf{handoff}.\par
\vspace{3mm}
\begin{block}{Last time, we taught the model a basic routine.}
Training examples taught it to inspect data and calculate with Python. Asking helpers reliably remained harder.
\end{block}
\vspace{2mm}
\begin{block}{This time, we studied the handoffs.}
Training improved a routine that uses helpers. Separately, we found that linking each helper answer to its input can substantially improve reading accuracy.
\end{block}
\smallnote{Alex Towell \quad | \quad Advisor discussion \quad | \quad Preliminary findings, 11 September 2026.}
\end{frame}

\begin{frame}[t]
\frametitle{We used supervised fine-tuning (SFT)\\to teach the main model a routine.}
SFT updates a model to imitate the demonstrated action for the situation it sees. Here is a simplified example, after a helper has replied.\par
\vspace{1mm}
\begin{columns}[T,onlytextwidth]
\begin{column}{0.47\textwidth}
\begin{block}{What the main model sees}
Task: Count the questions asking for a location.\par\medskip
The Python list \texttt{types} holds the helper's replies:\par\medskip
\texttt{location, human being, location}
\end{block}
\end{column}
\begin{column}{0.47\textwidth}
\begin{block}{What it learns to produce}
{\ttfamily\small
count = 0\par
for kind in types:\par
\hspace*{2em}if kind == "location":\par
\hspace*{4em}count += 1\par
print(count)\par}
\end{block}
\end{column}
\end{columns}
\vspace{2mm}
Python prints \textbf{2}. The training target is the action that calculates it, not just the number.
\smallnote{Illustrative data and shortened code, not a literal training record. Two copies started from the same earlier-trained model; each learned from 72 complete worked interactions. The helper stayed unchanged. [S1--S3]}
\end{frame}

\begin{frame}[t]
\frametitle{We changed how helper answers\\are linked to the text they describe.}
Separate helper test: decide whether a statement follows from a short text.\par
\vspace{1mm}
Example text: \emph{Maya bought a red bike.}\par
\vspace{1mm}
\begin{columns}[T,onlytextwidth]
\begin{column}{0.47\textwidth}
\begin{block}{The input carries matching names.}

\texttt{z2pm}: The bike is blue.
\end{block}
\end{column}
\begin{column}{0.47\textwidth}
\begin{block}{Each answer carries the same name.}

Without these names, the answers are matched only by their position in a list.

\begin{frame}[t]
\frametitle{Smaller requests were faster than large requests\\with matching names in this local test.}
Each method judged the same 768 statements about short texts. We changed how many statements were sent to the helper together.\par
\vspace{2mm}
\centering
\renewcommand{\arraystretch}{1.15}
\begin{tabular}{lrr}
\toprule
Statements per request & Correct judgments & Total time \\
\midrule
48, without matching names & 49\% & 19 seconds \\
48, with matching names & 85\% & 91 seconds \\
16, without matching names & 81\% & 19 seconds \\
1, without matching names & 87\% & 31 seconds \\
\bottomrule
\end{tabular}
\par\vspace{2mm}
\raggedright
Times cover all 768 statements, not one request. Sending one statement at a time was faster here, but repeated more input text.
\smallnote{We used Qwen3-4B on one A100, with up to four requests at once. Times add the measured test blocks and exclude server startup. All 848 requests had valid formatting. Other setups may give different speeds. [E1]}
\end{frame}

\begin{frame}[t]
\frametitle{Next test: let the RLM program organize\\helper requests and match their answers.}
The main model would still choose what to ask. A new program component would handle groups of input items and their replies.\par
\vspace{4mm}
\centering
\begin{tikzpicture}[font=\small]
\node[card,text width=3.3cm] (a) at (0,0) {Group input items\\and give each\\a matching name.};
\node[card,text width=3.3cm] (b) at (4.8,0) {Send each group\\to a helper model.};
\node[card,text width=3.3cm] (c) at (9.6,0) {Match each reply\\to its input; report\\any missing answers.};
\draw[flow] (a)--(b);
\draw[flow] (b)--(c);
\end{tikzpicture}
\par\vspace{5mm}
\raggedright
Compare fixed group sizes with the current RLM and with one item per request, using the same tasks, models, and computing budget.
\par\vspace{3mm}
Success means a more reliable \textbf{final calculation}, not just better helper answers.
\smallnote{This is a proposal, not a proven improvement to complete solutions. Matching names is standard and cannot ensure correct reading. Learning when to change group size comes later.}
\end{frame}

\begin{frame}[t]
\frametitle{We have a promising handoff result\\and a focused next research question.}
\begin{block}{What we know so far}
Training examples helped the main model use helpers and calculate. Matching names improved the helpers' reading judgments without retraining.
\end{block}
\vspace{2mm}
\begin{block}{What we want to establish next}
Can the proposed program change improve the final answer at an acceptable cost in time and computation?
\end{block}
\vspace{3mm}
{\large Would this be a worthwhile next study? What realistic task would make the test convincing?}
\smallnote{The larger goal remains learning how to divide unfamiliar problems into useful smaller ones. Today's evidence is narrower. End of the main talk; the remaining pages are optional discussion material.}
\end{frame}
