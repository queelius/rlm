\begin{frame}[t]
\frametitle{How can a model solve an unfamiliar task?}
We want a language model to discover useful steps, use tools, and check whether the job is finished.
\medskip

\textbf{A simple test: make a pickaxe in a crafting game.}
\begin{center}
\begin{tikzpicture}[every node/.style={font=\normalsize,align=center},box/.style={fill=Soft,text width=3.45cm,minimum height=1.5cm,inner sep=5pt}]
\node[box] (a) at (0,0) {Look up the\\needed recipes.};
\node[box] (b) at (4.45,0) {Make the parts\\and assemble them.};
\node[box] (c) at (8.9,0) {Check that the\\pickaxe was made.};
\draw[->,thick,Teal] (a)--(b);
\draw[->,thick,Teal] (b)--(c);
\end{tikzpicture}
\end{center}
The game checks actual success, not whether the answer sounds convincing.
\medskip

The larger idea is a \textbf{recursive language model (RLM)}: a model that can use code and ask helper models to solve smaller parts.
\aside{Simplified example. Our recent crafting experiments use one model with tools; they do not yet test recursive helper calls.}
\end{frame}

\begin{frame}[t]
\frametitle{We tried learning from success and failure.}
In \textbf{reinforcement learning (RL)}, the model tries answers or actions, receives a score, and learns from the feedback.
\begin{block}{We saw some gains, but not reliable progress in planning.}
Some models answered or selected information better. The gains often weakened on new examples, or did not clearly beat more learning from worked examples.
\end{block}
\begin{block}{Why is rewarding a finished task tricky?}
The model asks for a recipe, makes a wrong part, corrects it, and finishes the pickaxe. A reward for finishing does not say which earlier steps helped.
\end{block}
\textbf{Next RL question:} How can feedback teach useful steps, not just reward the final result?
\aside{This illustrates one possible challenge. It has not been proven to explain all our RL results.}
\end{frame}

\begin{frame}[t]
\frametitle{Can examples teach the model how to find the steps?}
We trained the model to imitate actions from worked examples. The goal is to make a pickaxe.
\begin{columns}[T,onlytextwidth]
\begin{column}{.48\textwidth}
\begin{block}{Teacher knows the recipes}
It plans the parts first, then demonstrates recipe lookups and crafting.
\end{block}
\end{column}
\begin{column}{.48\textwidth}
\begin{block}{Teacher discovers the recipes}
It looks up the pickaxe, finds its parts, then chooses the steps.
\end{block}
\end{column}
\end{columns}
Both examples show lookups. Only the second uses their answers to choose the route.
\medskip

Successes out of 32 attempts: \textbf{discovery examples: 15, then 10;} \textbf{known-recipe examples: 5, then 3.}
\aside{Simplified examples; both training packages differ in other ways. Two training repeats in the same game, not independent datasets.}
\end{frame}

\begin{frame}[t]
\frametitle{Who should supply the exact ingredients?}
The model chooses the next step and amount:\quad ``Make one pickaxe.''
\begin{center}
\begin{tikzpicture}[every node/.style={font=\normalsize,align=center},box/.style={fill=Soft,text width=3.5cm,minimum height=1.45cm,inner sep=5pt}]
\node[box] (a) at (0,0) {Model chooses what to make.};
\node[box] (b) at (4.4,0) {Code fills ingredients from a recipe already looked up.};
\node[box] (c) at (8.8,0) {Game checks whether it worked.};
\draw[->,thick,Teal] (a)--(b);
\draw[->,thick,Teal] (b)--(c);
\end{tikzpicture}
\end{center}
\textbf{Example:} The model asks to make one pickaxe. Code supplies the ingredient list from the recipe the model already found.
\medskip

No extra model training. On the first test of additional goals, success was \textbf{7 of 16 without code} and \textbf{10 of 16 with code}.
\aside{This changes how the command is carried out, not the model's choice of goal. Early result in the same game; broad transfer is not established.}
\end{frame}

\begin{frame}[t]
\frametitle{What are we testing now, and what comes next?}
\textbf{Running now:} On new crafting goals and recipes, compare both teaching methods with and without code assistance.
\medskip

\textbf{This tests two questions:} Does code help on new goals? Does the discovery advantage remain when code fills in the ingredients?
\medskip

\textbf{Proposed RL follow-up:} Test reward learning with and without code assistance. We have not fixed the design yet.
\medskip

\textbf{Longer term:} Learn when to ask a helper, or break a difficult part into smaller steps.
\begin{block}{For discussion}
What other multi-step task would make this useful?
\end{block}
\aside{The broader crafting comparison is underway. RL and learned helper use are future research, not current results.}
\end{frame}
